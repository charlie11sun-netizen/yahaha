## 0. 背景与总判断

平台生成物是**纯前端 HTML/CSS/JS bundle**。玩家侧运行时边界已具备两层——`<iframe sandbox="allow-scripts allow-pointer-lock">`（无 `allow-same-origin`）+ 发布时向 `index.html` 注入的 CSP（`default-src 'none'; connect-src 'none'`，见 `packaging.inject_csp`）。真正**裸奔的是服务端构建期**：生成代码在 worker 进程内用 `py_mini_racer` 直接冒烟（`app/agents/smoke.py`），且**引擎不可用时 fail-open 放行**（`return True, "skipped (engine unavailable)"`）；所有容器均无 `mem_limit` / `cpus`，worker 无 `--concurrency`。

因此优先级 1 的重心**不是给游戏加沙箱**（浏览器侧已有），而是：把构建期执行搬进**真容器**、把 **fail-open 改成 fail-closed**、给全链路补**资源 / 成本限额**。

### 决策记录

| 决策点 | 结论 |
| --- | --- |
| 服务端沙箱形态 | 常驻 sandbox-runner 容器（Playwright + Chromium），**容器本身是安全边界**；不用 docker socket 按需起容器，不用 Firecracker；生产可切 gVisor runtime |
| SVG 上传 | 移出白名单，直接拒绝 |
| ZIP 上传 | 保留，只读中央目录校验（条目数 / 解压总量 / 压缩比），**永不服务端解压** |
| 审核 provider | `MODERATION_PROVIDER=llm` 为生产默认，`blocklist` 为离线默认（保住「compose up 离线可跑」的 README 承诺） |
| 公开 Demo | **门禁分层**：浏览 + 游玩匿名可达，注册 / Create / Studio 仍在密码门后 |
| 观测顺序 | Sentry → 结构化日志 → 按次 usage/成本 → OTel → 失败链路 |

## 批次 A：构建期真沙箱 + 资源限制

> 无 schema 变更，不需要迁移。工作量约 4–5 人日。**已落地：`sandbox/` 服务、worker 集成、compose 资源限制、每用户并发槽位、恶意样本回归集。**

### A1. sandbox-runner 服务（新组件 `sandbox/`）

**形态**：Python FastAPI + Playwright（与主栈同语言），单容器常驻，接口只在内网可达。

**API 契约**：

| 端点 | 入参 | 返回 |
| --- | --- | --- |
| `POST /run` | `{files:[{path,content_b64}], entry, timeout_ms, simulate_input:bool}` | `{ok, page_errors[], console_errors[], frames_observed, load_ms, screenshot_b64?}` |
| `GET /health` | — | `{status}` |

**执行模型（关键设计）**：

- 每次运行开**全新 incognito context**；bundle 文件**不落盘**——用 Playwright `page.route()` 把假 origin（如 `https://bundle.sandbox/`）的请求映射到内存文件表，**其余所有请求一律 `abort`**。这样除 CSP 外多一层网络硬拦截，且免掉 tmpfs 文件管理。
- 注入 init script 包一层 `requestAnimationFrame` 计数器 → 拿到「有没有游戏循环在跑」的真实信号；收集 `console` / `pageerror` 事件；可选模拟几次按键（方向键 / 空格）验证输入处理不崩。
- 每次运行**硬超时杀 context**；服务内并发信号量 1–2；每 M 次运行重启 browser 进程（防泄漏累积）。

**容器加固（dev 与 prod compose 一致）**：

```yaml
sandbox:
  networks: [sandbox_net]      # internal: true，无 egress，仅 worker 可达
  read_only: true
  tmpfs: [/tmp]
  mem_limit: 768m
  cpus: "1.0"
  pids_limit: 256
  security_opt: ["no-new-privileges:true"]
```

- **Chromium 自身沙箱的取舍**：`cap_drop: ALL` 会破坏 Chromium 的 user-namespace 沙箱。**首选**挂标准 chromium seccomp profile 保住浏览器自带沙箱；若镜像调不通，**可接受 `--no-sandbox` 降级**——理由是容器已无网络、只读 FS、资源受限，生产再叠 gVisor。此取舍需写进 `安全与可观测性.md`。
- **生产**：`docker-compose.prod.yml` 里 sandbox 服务加 `runtime: runsc`（注释说明宿主机需装 gVisor；Zeabur 等托管不支持时回退加固版 runc）。兑现文档里「gVisor 接口边界已预留」的承诺。

### A2. worker 集成与 fail-closed

- 新增 `backend/app/services/sandbox_client.py`：httpx 客户端 + `SANDBOX_URL`；结果映射为结构化 `SandboxResult`。
- **执行顺序**：静态校验 → `py_mini_racer` 快速预检（毫秒级 fail-fast，保留）→ sandbox-runner 真浏览器执行。浏览器信号（page error、零帧、console error）进 `gameplay_qa_node` 判定：**加载即错 / 零帧 = 硬失败走 repair**；console warning = 软警告。信号同时存入 state，为后续「QA 失败原因回灌 coder」备好数据。
- **`SANDBOX_REQUIRED`**（compose 默认 true，裸跑 pytest 默认 false 用 mock）：为 true 时 sandbox 不可达 → 步骤失败、`error_code=SANDBOX_UNAVAILABLE`（可重试），**顺带消灭 `smoke.py` 引擎缺失即放行的 fail-open**；为 false 时降级用 mini_racer 结果并打日志。

### A3. 资源限制铺满

| 服务 | mem_limit | cpus | 备注 |
| --- | --- | --- | --- |
| api | 512m | 1.0 | |
| worker | 1g | 1.5 | 命令加 `--concurrency=2 --max-tasks-per-child=20`；config 加 `worker_max_memory_per_child` |
| beat | 256m | 0.5 | |
| sandbox | 768m | 1.0 | Chromium 需余量 |
| postgres / redis / minio | 适度 | | 防互相挤压即可 |

**不变量**：保持 `visibility_timeout(7200) > time_limit(1800)`，本批不动这两个值。

### A4. 每用户并发槽位

- 落点：`POST /tasks`（create 与 revision 两个入口）。用 **DB 查询**该用户 status ∈ (PENDING, RUNNING) 的任务数（比 Redis 计数免 TTL 漂移；`time_limit` 保证任务终会进终态），需要 `(user_id, status)` 索引。
- `MAX_ACTIVE_TASKS_PER_USER=2`，超限返回 **409 + `TOO_MANY_ACTIVE_TASKS`**。既有 IP 限流（20/小时）不动，两者正交。

### A5. 恶意样本回归集

`backend/tests/fixtures/malicious_bundles/` + 集成测试（CI 里以 service container 跑 sandbox）：死循环、内存炸弹、fetch 外联、`window.top` 探测、`setInterval` 风暴。断言：**超时被杀 / 请求被 abort / 每个样本跑完后 `/health` 仍 OK**。

### A 批次验收

- 恶意样本集全部被杀 / 拦且 sandbox 服务存活；
- `SANDBOX_REQUIRED=true` 时断掉 sandbox 服务，任务必失败（非放行）；
- `docker stats` 可见各容器内存上限生效；
- 同一用户第 3 个并发任务被拒（409）。

## 批次 B：上传硬化 + 内容审核（可与 A 并行）

> 迁移 `0002`：`Asset.scan_status` + `moderation_events` 表。工作量约 4–5 人日。**已落地**：上传嗅探/图片重编码/ZIP 校验/可选 ClamAV、统一内容审核与审计表、主要同步入口和生成前 `safety_intake` 接入。

### B1. 上传管线（新模块 `backend/app/services/upload_safety.py`）

单文件处理顺序：现有大小 / 数量检查 → 读字节 → **`filetype` 嗅探**（纯 Python，Windows 开发机免 libmagic）→ 按类型分派：

| 类型 | 策略 |
| --- | --- |
| JPEG / PNG / WebP | **Pillow 重编码**：先 `ImageOps.exif_transpose`（防剥 EXIF 后方向翻转），再同格式重编码。一步拿三收益：EXIF/GPS 清空、polyglot 文件被打碎、畸形图被拒。设 `Image.MAX_IMAGE_PIXELS` 并捕获 `DecompressionBombError`；尺寸 >8192px 拒绝 |
| GIF | 无 EXIF、动图重编码复杂——只做嗅探一致性校验，直传 |
| SVG | **拒绝**：声明 `image/svg+xml` 直接 415；声明其他 `image/*` 但内容为 XML/SVG 文本的，因嗅探不符同样 415 |
| video / audio / pdf | 嗅探族别与声明一致才收；否则 415 |
| json / text | 无 magic：要求 UTF-8 可解码且不命中任何已知二进制 magic |
| ZIP | 内存中 `zipfile` 读中央目录：条目 ≤200、解压总量 ≤100MB、压缩比 ≤100、拒绝加密条目；**永不解压** |

- 存储时 Content-Type 一律以**嗅探结果**为准（不再信客户端上报）。
- **预签名 URL**：非图片类统一加 `response-content-disposition=attachment`（图片已重编码，可 inline）——封死「上传伪装文件被当 HTML 打开」的 XSS 面。
- **ClamAV 可插拔**：compose 加 optional profile `scan`（`clamav/clamav:stable`，其内存约 1–1.5G，故设为可选）；`UPLOAD_SCAN=off|clamav`，开启时上传同步走 clamd INSTREAM（10MB 内 <1s），clamd 不可达则上传接口 503（fail-closed，上传非关键路径可接受）。`Asset` 加 `scan_status`（skipped / clean / blocked）；启用扫描时以 clean 表示可用，off 模式下 skipped 保持离线默认可跑。

新依赖：`filetype`、`Pillow`（均有 wheels）、`clamd`（可选）。

### B2. 内容审核（新模块 `backend/app/services/content_safety.py`）

**统一入口**：`moderate_text(text, surface, user_id) -> {action: allow|flag|block, categories, provider, latency_ms}`

**Provider**（`MODERATION_PROVIDER=off|blocklist|llm`）：

- `blocklist`：把现在 `safety_intake` 里的黑名单抽到这里，归一化匹配；**离线默认**。
- `llm`（**生产默认**）：复用现有 `app/agents/llm.py` 客户端做一次分类调用——temperature 0、`response_format` 强制 JSON、输入截断 4k 字符、超时 10s、类别集（sexual_minors / violence_extreme / hate / self_harm / illegal / harassment / spam）+ 严重度。审核 prompt 遵守文档 1.3 原则：被审文本是 **data 不是指令**。
- **Redis 缓存**：`sha256(text)` → 结果，24h，同内容去重省成本。
- **灰度开关 `MODERATION_MODE=log|enforce`**（默认 log）：上线首周只记录不拦截，观察误伤率后再切 enforce——审核最大风险是误杀，必须留退路。
- **失败策略**：provider 报错时 fail-open 放行 + 落一条 `action=error` 事件（避免审核服务抖动放大成全站不可用）。

**挂载点与动作**：

| 挂载点 | 时机 | block 行为 |
| --- | --- | --- |
| 创意 idea + 文件名 | `safety_intake` 节点内（复用现有 SAFETY_REJECTED 展示链路） | 任务失败 `MODERATION_BLOCKED` |
| 标题 / 简介 / 标签 + AI 产出对外文案 | publish 接口同步 | 422 |
| 评论 | POST 同步 | 422（MVP 不建软隐藏队列，block-only） |
| 昵称 / 资料 | 注册 / 更新同步 | 422 |
| 记忆 raw_text | 创建同步 | 422 |

**审计表 `moderation_events`**：surface、object_id、user_id、action、categories(json)、provider、input_sha256、input_excerpt(200 字)、latency_ms、created_at；索引 `(surface, created_at)`。

### B 批次验收

- 伪造 Content-Type 的 HTML / SVG 上传被 415；
- 上传含 GPS EXIF 的 JPEG 下载回来**无 EXIF**；
- zip bomb 被拒；
- 违规 prompt 得到 `MODERATION_BLOCKED` 而非生成；
- `moderation_events` 有完整记录。

## 批次 C：可观测性与成本

> 迁移 `0003`：`llm_calls` 表、`task.cost_usd`、`task.failed_stage`、`steps.attempt` / `caused_by_step_id`。工作量约 5–6 人日。
> 落地状态：已施工（Sentry / 结构化日志 / request_id 贯通 / LLM usage 与成本 / OTel / 失败链路 / ops SQL）。

### C1. Sentry（半天）

- `sentry-sdk[fastapi,celery]`；统一在新的 `app/core/telemetry.py::init_sentry()`，api 与 worker 两入口各调一次；`SENTRY_DSN` 空 = 关闭。
- 隐私：`send_default_pii=False`，`before_send` 剥离请求体、prompt、邮箱；tags 带 request_id / task_id / agent。`traces_sample_rate=0`（trace 交给 OTel，避免双份）。

### C2. 结构化日志（1 天）

- structlog：`LOG_FORMAT=json`（prod 默认）/ console（dev）。绑定 contextvars：request_id（middleware）、user_id（鉴权依赖处）、task_id + agent（worker 内由 pipeline / `tracing.logged` 绑定）。
- **request_id 跨进程**：API 发 Celery 任务时塞 headers，worker `task_prerun` 信号读出并绑定——接上现在「API 有 ID、worker 里断掉」的链路。uvicorn / celery 原生 logger 也路由进 structlog formatter，保证全量 JSON。

### C3. 按次 LLM usage 与成本（1.5 天，是 A' 预算的地基）

- `llm.chat` 返回值从 `tuple[str, int]` 改为 `LLMResult(text, prompt_tokens, completion_tokens, total, model, latency_ms)`；约 20 处调用点机械更新，state 里 `_tokens_delta` 语义不变（仍是 total）。
- 新表 **`llm_calls`**：task_id、step_id、model、prompt_tokens、completion_tokens、total_tokens、latency_ms、retried、cost_usd `numeric(10,6)`、created_at。task / step 上下文由 tracing 设 contextvar 提供。
- **顺手修历史欠账**：`finish_step` 本来就收到 tokens 参数，补一行写入 `AgentStep.tokens`（该列建表以来从未写过）。
- 定价：`MODEL_PRICING_JSON` env（`{"gpt-5.5":{"in":1.25,"out":10.0}}`，$/1M），config 内置默认表；未知模型 cost 记 NULL 不瞎算。`GenerationTask.cost_usd` 聚合列，`serialize.py` 带给前端（Create 页已显示 tokens，加一行成本）。
- 聚合先不做面板：新增 `docs/ops-queries.md` 收录 SQL——日成本、每个成功游戏均价、失败任务浪费额、各节点烧钱排行。

### C4. OpenTelemetry（1–1.5 天）

- 自动埋点：`opentelemetry-instrumentation-{fastapi,sqlalchemy,redis,celery,httpx}`（openai 客户端底层即 httpx）；`OTEL_EXPORTER_OTLP_ENDPOINT` 空 = no-op。
- **节点级 span**：在现成的 `tracing.logged` 装饰器里包 `agent.{node_name}` span（attributes：agent、tokens、repair/replan 计数）——tracing.py 就是天然埋点位，改动集中一处。
- CeleryInstrumentor 自动做 traceparent 传播 → 「一次点击 → API → 队列 → 22 节点」一条完整 trace。
- dev compose 加 optional profile `otel`：Jaeger all-in-one（自带 OTLP 4317 接收，dev 不需单独 collector）；生产指向任意 OTLP 后端。采样率 env 控制（dev 1.0 / prod 建议 0.2）。

### C5. 失败链路（1 天）

- `app/core/errors.py::TaskErrorCode` 枚举：`SAFETY_REJECTED` / `MODERATION_BLOCKED` / `PROMPT_TOO_LONG` / `MODEL_TIMEOUT` / `MODEL_INVALID_OUTPUT` / `VALIDATION_FAILED` / `SMOKE_FAILED` / `QA_FAILED` / `SANDBOX_UNAVAILABLE` / `BUDGET_EXCEEDED` / `PUBLISH_FAILED` / `CANCELLED` / `UNKNOWN`；扫一遍现有散落字符串统一到枚举。
- `GenerationTask.failed_stage`（失败在哪个节点）；`agent_steps` 加 `attempt`（同一 agent 第几次跑）与 `caused_by_step_id`（repair 指回触发它的失败步骤）——repair→replan 链条从此可完整重建，而非只有两个总次数。
- 产出：`ops-queries.md` 里的节点失败率漏斗 + error_code 分布。这份数据同时是「QA 失败原因回灌 coder」和生成质量迭代的依据。

### C 批次验收

- 一个失败任务能在 Sentry 看到带 task_id 的异常、在 Jaeger 看到完整 trace、在 DB 查到每次 LLM 调用的 token / 成本、error_code 定位到具体节点与第几次尝试。

### A'. Token 硬预算（C3 之后，半天）

- `TASK_TOKEN_BUDGET`（如 300k，0 = 关闭），可选 `TASK_COST_BUDGET_USD`。
- 执行点：tracing 累计 tokens 处——与 `begin_step` 检查 CANCELLED 同一位置，语义对齐（抛 `TaskBudgetExceededError` → pipeline 捕获 → FAILED + `BUDGET_EXCEEDED`）。**公开 Demo 实例必开**。

## 批次 D：产品闭环

> 迁移 `0004`：`games.remixed_from_game_id` / `remixed_from_version`、`gameversion.created_at`（如缺）。工作量约 6 人日。
> 落地状态：已施工（版本列表 / 激活回滚 / owner 指定版本 manifest、Remix 任务与新 Game 溯源、公开浏览门禁分层、Caddy edge profile、独立 Playwright E2E 与 CI job）。

### D1. 版本切换（1 天）

- API（games router）：
  - `GET /games/{id}/versions`（owner）→ `[{version, created_at, size_bytes, sha256, is_current}]`（`GameVersion` 若缺 `created_at` 列，随本批迁移补上）。
  - `POST /games/{id}/versions/{v}/activate`（owner）：改 `current_version`，**已发布游戏也允许 = 一键回滚**，这是功能最大价值；前置校验该版本 manifest / bundle key 完整。
  - manifest 端点已按 current_version 读，无需改；另给 manifest 加 owner-only 的 `?version=` 参数支撑逐版本预览。
- 前端：游戏管理视图加版本面板（时间 / 大小 / 设为当前 / 预览）。
- 产物保留策略（留最近 N 版控 S3 成本）明确**不做**，留作后续旋钮。

### D2. Remix（2 天）

- 迁移：`games.remixed_from_game_id`（FK, nullable）+ `remixed_from_version`。
- API：`POST /tasks` 支持 `task_kind="remix"` + `source_game_id`；校验源游戏 published 或本人所有。机制上是「跨游戏的 revision」：state 注入源游戏 spec + design + game.js（截断上限约 60k 字符控 token）+ 用户新 prompt，走既有图；产出**新 Game**（v1）并写 remixed_from。
- 幂等语义延续既有约定：remix 的发布同样按 `source_task_id` 幂等。
- 前端：Play / 详情页 Remix 按钮 → Create 页预填；详情页展示「Remix 自 X by Y」链接；原作显示被 Remix 数。
- 限额复用批次 A 的槽位与预算，发布时过批次 B 的审核。

### D3. 门禁分层公开 Demo（1–1.5 天）

- 新开关 `GATE_PUBLIC_BROWSE`（默认 false = 现行为，demo 实例设 true）：
  - **前端 `middleware.ts`**：白名单 `/`、`/explore`、`/games/*`、`/play/*`、`/gate`、`_next/*` 静态资源；auth / create / me / studio 仍拦。
  - **后端 `core/gate.py`**：对应放行 `GET /games*`、`GET .../manifest`、`POST .../play`（已有防刷 + 限流）、分数上报与排行 GET（匿名玩家名已有 80 字限制 + 限流）、`/health`；其余照旧要 `X-Gate-Token`。
- Demo 实例安全阀：`TASK_TOKEN_BUDGET` 收紧 + 槽位 = 1 + 注册限流（已有）；是否开真模型由部署者按预算定，`DEPLOY.md` 写清组合建议。
- TLS：compose 加 optional profile `edge` 的 Caddy 反代（自动 Let's Encrypt，web / api / minio 收敛到一个域名），`PUBLIC_*` 三个 URL 与 CORS 相应改写；走 Zeabur 则天然有 TLS。两条路径都写进 `DEPLOY.md`。seed 的 3 个旗舰游戏保证 demo 开箱不空。

### D4. Playwright E2E（1.5–2 天）

- 顶层新目录 `e2e/`（独立 package.json，不污染 frontend 构建）；baseURL 走 env；global-setup 轮询 `/health/ready`。
- 首批 8 条：注册登录登出 + 未登录访问 /create 重定向；Create 全链路（mock 模型：提交 → 步骤流完成 → 预览 iframe 出现 → 发布 → Explore 可见）；Play（seed 游戏 iframe 加载成功、无错误态；跨源 frame 用 Playwright frames API 断言）；点赞 / 评论；门禁页密码流程；D1/D2 落地后补版本切换与 Remix 各一条。
- 确定性：`USE_REAL_MODEL=false`；mock 流水线秒级完成，UI 轮询给宽松超时。
- CI 新 job：`docker compose up -d --build` → 等 ready → `npx playwright test`，失败上传 trace / 截图 artifact，整 job 限时 15 分钟。
