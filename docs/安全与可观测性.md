## 1. 安全方案（安全隔离）

> 覆盖需求点：上传素材、Prompt Injection、任意生成代码执行、密钥保护、资源限额。

### 1.1 三层隔离总览

| 层 | 边界 | 手段 |
| --- | --- | --- |
| **生成时** | Sandbox QA 执行生成代码 | 静态规则 + worker 进程内 V8 快速预检 + 常驻 `sandbox` 容器内 Playwright/Chromium 真浏览器 QA；`sandbox_net` 内网可达、无对外 egress、只读文件系统、CPU/内存/PID 限制 |
| **运行时** | Play 跑远端 bundle | `<iframe sandbox="allow-scripts allow-pointer-lock">`（**不含 `allow-same-origin`**）+ 独立 OSS 源 + **发布时向 index.html 注入 CSP**（`default-src 'none'; connect-src 'none'` 等，浏览器层强制 manifest 的 `network:false`；`packaging.inject_csp`）|
| **数据/网络** | 前端 ↔ 存储/库 | 前端只经 REST + HttpOnly JWT Cookie；写请求校验 `Origin` 防 CSRF；`uploads/` 私有并走短期签名 URL，`games/` 匿名只读；DB 仅后端可达 |

### 1.2 上传素材

- **类型白名单**：仅 `image / video / audio / PDF / JSON / ZIP / text`；当前按上传声明的 Content-Type 校验，尚未做内容级 MIME 嗅探。
- **限额**：单任务 ≤6 个文件（对齐设计稿）、单文件大小上限、总量上限。
- **存储隔离**：落 `uploads/{userId}/{assetId}/…` 私有前缀，通过一小时签名 URL 读取；图片 EXIF 清理尚未实现。
- **扫描**：病毒 / 内容审核为可插拔步骤（MVP 可 Mock，返回 clean，但接口边界保留）。

### 1.3 Prompt Injection

- 创意 brief、文件名、素材文本一律视为**不可信数据**，不是指令。
- System prompt 与用户内容**物理分离**，用结构化工具调用 / 字段传参，不做字符串拼接注入。
- Planner 把创意当 `data` 解析成 `game-spec.json`，不执行其中的"指令式"文本（如 "ignore previous / 导出密钥"）。
- 生成代码限制在**白名单运行时**（canvas/DOM），禁止 `fetch/XHR/eval` 远端、禁止外链；由 Sandbox QA 静态扫描拦截。

### 1.4 任意生成代码执行

- 生成代码**绝不在后端主进程执行**。
- **生成时**：worker 先用 `py_mini_racer` 做毫秒级加载期预检，再把完整 bundle 发给独立 `sandbox` 服务。`sandbox` 用 Playwright `page.route()` 将 `https://bundle.sandbox/` 映射到内存文件表，其他请求一律 abort；每次运行新建 browser context，收集 page error、console error、被拦截请求和 `requestAnimationFrame` 帧数。
- **Chromium 沙箱取舍**：官方 Playwright Docker 文档建议不可信页面使用非 root 用户 + seccomp profile。当前 compose 默认 `SANDBOX_RUNNER_CHROMIUM_NO_SANDBOX=true`，即浏览器自带沙箱降级，原因是 dev/托管环境不一定能挂完整 Chromium seccomp profile；安全边界主要由独立容器、内部网络、只读 FS、tmpfs、资源限制和生产可选 gVisor (`SANDBOX_RUNTIME=runsc`) 叠加提供。具备 seccomp/user namespace 条件的宿主机可把该变量设为 `false` 后再启用浏览器自带沙箱。
- **运行时**：浏览器 sandboxed iframe 无 `allow-same-origin`，无法读父页面 DOM / Cookie / localStorage；bundle 由独立 OSS 源提供。
- **完整性**：manifest 保存 sha256 供审计展示；前端尚未重新下载并比对 bundle 哈希。

### 1.5 密钥保护

- 模型 API Key、OSS 凭证、OAuth client secret **只存后端/worker**，从不下发前端。
- `.env` + secret manager 注入；仓库只提交 `.env.example`（占位，无真实值）。
- 上传素材使用短期签名 URL；可播放的 `games/` 产物为公网只读。OAuth 回调直接设置 HttpOnly 会话 Cookie，本站 token 不再进入 URL、JS 内存或 `localStorage`。

### 1.6 资源限额

| 维度 | 限额 |
| --- | --- |
| 生成任务 | 按 IP 创建频率限制 + 每用户活动任务槽位 `MAX_ACTIVE_TASKS_PER_USER`（默认 2，超限 409） |
| Token 成本 | `tokens_used` 累计展示；尚无单任务硬预算 |
| 沙箱 | `sandbox` 容器：`mem_limit=768m`、`cpus=1.0`、`pids_limit=256`、`read_only`、`tmpfs=/tmp`、内部网络；worker `--concurrency=2 --max-tasks-per-child=20` |
| 上传 | 文件大小 / 数量 / 总量上限 |
| 产物 | bundle 体积上限 |
| API | 按 IP / 用户限流 |

### 1.7 鉴权与访问控制

- 受保护接口（Create、`/uploads`、`publish`、`like`）强制 HttpOnly Cookie 会话；Bearer 请求头不再是认证通道，退出会立即清除 Cookie。
- 资源 owner 校验：仅作者可 `preview` / `publish` 自己的 `preview` 游戏。
- 仅 `published` 游戏对外可见；`draft/preview` 不进 Home。

## 2. 失败恢复

> 覆盖需求点：模型输出不稳定、构建失败、上传失败、发布失败、加载失败。

| 失败点 | 检测 | 恢复策略 | 用户可见 |
| --- | --- | --- | --- |
| **模型输出不稳定/不合法** | `game-spec.json` schema 校验、生成代码语法检查 | 节点级**重试 + 退避**；超 N 次降级到模板；LangGraph 回边 | 步骤标红 → `task.failed` + error；可 Regenerate |
| **构建失败**（bundle 不合法） | Coder/Sandbox QA 校验失败 | 图内 repair 回边；任务级 Retry 从失败节点 replay | Retry 按钮 |
| **上传失败**（OSS） | boto3 异常 / 校验 | 幂等 key + 重试；失败置 `task.failed`，**不产出半成品** | 任务失败可重试 |
| **发布失败** | 事务异常 | `status → published` 与 `published_at` **原子提交**，失败回滚保持 `preview` | 提示发布失败，可重发 |
| **加载失败**（Play） | manifest/bundle 404、`sha256` 不符、iframe 错误 | 统一 **error 态，不白屏**（对齐设计稿）；Retry / 返回首页 | 错误原因 + 两个出口 |
| **Worker 崩溃/中断** | Celery 心跳 + LangGraph thread | Celery `acks_late` 重新投递；`PostgresSaver` 从最新成功 super-step 续跑 | 任务自动恢复，悬挂步骤标记 failed |
| **Checkpoint DB 短暂不可用** | psycopg / saver 异常 | 不改写业务失败态，Celery 持续重试当前 delivery | 任务保持 pending/running |
| **Redis 事件通道不可用 / SSE 断线** | 发布异常熔断日志、SSE `unavailable` 事件或浏览器读流失败 | Redis 只传失效信号，不承载业务状态；前端指数退避重连，并由 React Query 每 30 秒从 PostgreSQL 真源兜底刷新 | 页面显示重连状态，任务执行与事务不受影响 |

**关键机制**：图内 repair/replan、LangGraph `PostgresSaver`、Celery `acks_late`、发布走 DB 事务、产物**先 `preview` 后 `publish`**。

## 3. 可观测性

> 覆盖需求点：生成过程、Agent 输入输出、用户操作、错误日志、演示证据。

| 维度 | 落地 |
| --- | --- |
| **生成过程** | `agent_steps` + `agent_logs` 持久化每步状态与日志行 → 前端步骤流可实时看、可回放（设计稿 Create 黑底日志） |
| **实时任务状态** | Worker/API 在事务提交后向 Redis Pub/Sub 发布轻量失效信号；SSE API 合并突发通知、从 PostgreSQL 重新序列化完整快照，并以 15 秒 heartbeat 保持连接。Redis 不是第二真源 |
| **Agent 输入输出** | 每节点的 input/output（prompt、spec、代码摘要）落库（可截断/脱敏），逐步 `tokens` 计数 |
| **用户操作埋点** | `play_events`（游玩）落库；可扩展 like/publish 事件；Play 前后端核心业务埋点（加分项） |
| **错误日志** | 文本日志输出 stdout，每个 HTTP 响应带 `X-Request-ID`；尚未接结构化 JSON、Sentry 或 Loki |
| **指标**（可选） | 任务成功率、生成时延、token 成本、加载成功率 → Prometheus |
| **演示证据** | README 记录截图路径 + 关键日志导出；任务详情页 / Play 加载日志本身即天然 demo 证据 |

## 4. 已知问题与演进方向

| 现状（MVP） | 演进方向（再给 1 周） |
| --- | --- |
| gVisor 沙箱、病毒/内容审核可先 **Mock**（返回固定结果） | 接真实容器沙箱与扫描服务，接口边界已预留 |
| 多模态：图片走 vision，视频仅**存储 + 引用**，不做帧级理解 | 引入视频抽帧 / 多模态理解 |
| 生成多样性受 bundle 模板限制（设计稿用 srcdoc 模板） | 真实 codegen，Coder 产出更自由的 HTML5 工程 |
| OAuth 真跑通其一（如 GitHub），另一个给设计 | 补齐双 provider + 账号合并策略 |
| `plays_count` 同步自增 | 改 `play_events` 异步聚合，抗并发 |
| Play 无 CDN / 预取优化（加分项仅基础实现） | manifest 预取、bundle 缓存、加载骨架优化 |
| 单 worker、compose 单实例 | worker 水平扩展、队列分级 |
