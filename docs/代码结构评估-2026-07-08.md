## 一、确认的问题(按优先级)

### P1-1 services 层唯一的分层违例:content_safety 直接抛 HTTPException

- 证据:`backend/app/services/content_safety.py:10,276-277`(503 MODERATION_UNAVAILABLE / 422 MODERATION_BLOCKED)。
- 全 services + agents 仅此一处 import HTTPException,其余全部走 `ServiceError` + router `_run()` 翻译。这是昨天立下的约定,该文件漏改。
- 建议:改抛 `ServiceError(status_code, detail)`,调用方 router 已有统一翻译,预计改动很小。

### P1-2 前端类型契约仍靠手写,OpenAPI 链路没接上

- 证据:`frontend/lib/types.ts`(345 行手写类型);后端 response_model 覆盖率已近满(games 26/26、tasks 7/7、memory 9/9、auth 8/8、users 4/4,仅 oauth 的 2 个 redirect 端点无,属合理豁免)。
- 昨天给 routers 补 response_model 的目的就是作为类型生成来源,临门一脚没踢:`AgentLogEvent` 这类 20+ 可选字段的 union 是漂移最高危区,且无 zod/valibot 运行时校验兜底。
- 建议:接 openapi-typescript(或 orval)生成类型,手写 types.ts 收缩为前端专属视图类型。

### P1-3 巨型文件:后端 1 个、前端 4 个

- `backend/app/services/memory_profiles.py` **1800 行、约 80 个函数**,混杂 LLM 提取(`extract_profile_claims_batch` L864)、状态机(`_promote_candidate_if_ready` L1045、`_supersede_profile` L1005)、证据管理(`remove_evidence_from_profiles` L1567)、检索查询四类职责。可拆为 extraction / state_machine / evidence / queries 四模块,是后端唯一超千行且多职责的 service。
- 前端未套用 create/me 拆分模式的超重页面:`app/explore/page.tsx` **775 行**(单函数内联 10+ 卡片组件 + 画布动画)、`app/me/page.tsx` 569 行(大量 useState 与业务逻辑仍留在页面)、`app/page.tsx` 565 行、`app/play/[id]/page.tsx` 391 行。
- 已拆的 create 路由中 `_components/CreatePanels.tsx` 866 行,属于"把大文件搬了个家",面板可再按卡片分文件。

### P2-1 仓库卫生:生成产物入库与散落

- `graphify-out/` 有 **248 个文件被 git 跟踪**,其中大部分是 `cache/ast/v0.9.5/*.json` 哈希缓存;工作区还散落着未跟踪的 `graphify-out/2026-07-0*/` 日目录、`backend/celerybeat-schedule`。
- `frontend/gameweave-homepage-qa.png` 已入库但代码零引用(QA 截图遗留)。
- 建议:定一条策略——graphify-out 只跟踪 `graph.json` + `GRAPH_REPORT.md`(或整目录忽略),`cache/`、日期目录、`celerybeat-schedule`、`*.tsbuildinfo`(当前未入库,补进 .gitignore 防患)统一忽略;删除无引用的 QA 截图。

### P2-2 组件重复与共享层缺位(前端)

- `coverBackground()` 在 `frontend/components/GameCard.tsx:65` 与 `frontend/app/games/[id]/page.tsx:347` 逐字重复,应上提 lib。
- `components/` 目前只有 Nav、GameCard 和 shadcn ui/*;StatCard、Panel、Avatar 等通用容器散在 `app/me/_components/StudioPanels.tsx`(515 行、7 个导出),explore 里还有一批同类内联卡片。跨路由复用一旦发生就会再复制一份。

### P2-3 legacy CSS 体量(注意:scope 本身没问题)

- `frontend/app/legacy-pf.css` 5833 行。**已核实全部 834 个顶层选择器都限定在 `.pf-legacy-scope` 下**,昨天重构的声明属实,泄漏风险已被控制。
- 真正的问题是体量与双轨:除 `/` 和 `/gate` 外所有路由仍挂 legacy scope,Tailwind 只在零星处使用。这是"已被圈起来的债",不紧急,但每新增一个页面都在加深依赖。建议按页面逐个迁出(先小页面 about/privacy/terms 练手)。

### P2-4 backend/app/agents/code_agent.py 1270 行双职责

- repair 内环工具循环与作者模式 `run_author` 同居一个文件。它与 codegen.py 的边界是有设计依据的(codegen=一次性生成节点,code_agent=Agents SDK 内环),但文件内部 repair/author 两条产品线可拆。

### P2-5 vendored 引擎污染分析工具链

- `backend/app/agents/vendor/` 内 phaser.min.js(1.4M)+ three.min.js(596K)。离线注入 bundle 的设计是对的,不建议搬;但它污染知识图谱:god node `i()` 1151 条边、40+ 个"Three.js Vendor"假社区、以及 three→phaser 的假 INFERRED 边,都来自压缩代码。建议把 `backend/app/agents/vendor/` 加入 graphify 排除清单,图谱信噪比会大幅提升。

## 二、结构亮点(核实过)

1. **分层单向且有执行力**:services/agents 零 `from app.api`;routers 统一 `_run()` 把 ServiceError 翻译成 HTTP(games.py:34-38 模式全 router 一致);models 仅被合理引用。
2. **nodes.py 门面是承重墙,不是遗留物**:graph.py 经 `from app.agents import nodes` 单点接线;planning/codegen/repair 等子模块运行时经门面做 late-binding 属性查找,5 个测试文件靠它做 monkeypatch。这个缝设计得好,**不要退役**。
3. **tracing.logged 装饰器**把步骤落库、取消检查、token 预算从节点逻辑中完全剥离(agents/tracing.py),节点函数保持纯粹。
4. **测试替身集中**:conftest.py 85 行覆盖 db(SQLite)/Redis(_FakeRedis)/S3/celery 全部外部依赖,20 个测试文件与模块一一对应,离线可跑。
5. **门禁三件套职责清晰**:middleware.ts(Edge 验签)→ app/api/gate/route.ts(设 cookie)→ lib/gate.ts(双运行时工具),后端 core/gate.py 常数时间比较,前后端各管一半。
6. **迁移单基线**:squash 后 `backend/migrations/versions/0001_baseline.py` + 守护测试(test_migrations)保证新库可重放且与 ORM 一致。
7. **celery 配置集中**(tasks/celery_app.py 47 行),任务按域分文件,beat 调度一处可见。
