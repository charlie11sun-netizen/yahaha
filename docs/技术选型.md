# 技术选型

> 项目：AI Native 互动游戏平台 MVP（对应 `AI-Agent-全栈工程师-系统设计测试.md`）
> 更新日期：2026-06-18
> 决策原则：**2 天单人交付**，把风险降到最低。后端统一用 **Python**（开发者更熟），TypeScript 只保留在前端 UI；不掺第二门后端语言，让**同一门语言独占后端与数据库**（避免双 ORM 抢迁移权）。

---

## 1. 技术栈总览（对应交付项「技术栈」）

| 维度 | 选型 |
| --- | --- |
| **前端** | Next.js 15（App Router）+ React 19 + TypeScript |
| **后端** | Python + FastAPI |
| **数据库** | PostgreSQL 16（SQLAlchemy 2.0 + Alembic） |
| **对象存储** | MinIO（S3 兼容，boto3 访问） |
| **Agent 框架** | LangGraph（Python）+ LangChain |

| **部署方式** | Docker Compose（一键拉起全部依赖） |

## 2. 分层选型与理由

| 层 | 选型 | 关键包 | 为什么 |
| --- | --- | --- | --- |
| **前端框架** | Next.js 15 + React 19 + TS | `next` `react` `typescript` | 一套框架覆盖 Home / Create / Play；保留 SSR 让首页数据来自后端，符合「不接受写死前端数组」 |
| **UI** | Tailwind CSS v4 + shadcn/ui | `tailwindcss` `lucide-react` | 2 天内出像样界面最快的组合 |
| **数据请求 / 实时状态** | TanStack Query v5 + SSE | `@tanstack/react-query` `fetch` / ReadableStream | SSE 实时写入任务缓存；需携带门禁请求头，因此不用原生 EventSource；30 秒查询仅作断线兜底 |
| **后端 API** | FastAPI + Uvicorn | `fastapi` `uvicorn` `pydantic` | 异步原生、性能好；**自动生成 OpenAPI 文档**直接当「核心接口」交付物 |
| **数据库 / ORM** | PostgreSQL 16 + SQLAlchemy 2.0 | `sqlalchemy` `alembic` `psycopg` | 关系建模 用户/游戏/版本/素材/任务/Agent日志；Alembic 管迁移 |
| **认证** | fastapi-users + httpx-oauth | `fastapi-users` `httpx-oauth` | 邮箱注册/登录/登出 + Google/GitHub OAuth 一站式，覆盖 Auth 全部验收点 |
| **异步任务** | Celery + Redis | `celery` `redis` | 生成任务耗时长，需队列 + **失败重试** + 进度上报；worker 把状态/步骤写进 DB |
| **Agent 编排** | LangGraph（Python 原版） | `langgraph` `langchain-core` | 显式节点/边 → 好解释「为什么这样拆分」；自带 checkpoint（重试/恢复）+ 流式步骤（Agent 过程可见） |
| **模型调用** | langchain-openai | `langchain-openai` / `openai` | 接 Yahaha 的 GPT-5.5，改 `base_url` 即可；图片输入走 vision，provider 可换 Claude |
| **对象存储** | MinIO + boto3 | `boto3` | MinIO 本地模拟 S3；**boto3 是 AWS 官方 SDK，换真 S3/阿里云 OSS 只改 endpoint**，满足「无缝迁移」硬要求 |
| **部署** | Docker Compose | — | 一条命令拉起 web/api/worker/postgres/redis/minio |

## 3. 选型背后的关键架构决策

这次测试的难点不在 CRUD，而在 5 个硬骨头。选型本质上就是在服务这 5 点：

1. **Play 安全隔离 = 沙箱化 iframe。**
   生成物是自包含的 HTML5 游戏，Play 页用 `<iframe sandbox>` + CSP 加载 MinIO 远端 URL。iframe 本身就是隔离边界，**MVP 不需要服务端执行任意生成代码**——这是最安全、最易讲清的设计。（与后端语言无关）

2. **远端产物协议 = `manifest.json` + `index.html` + assets。**
   存于 MinIO 的 `games/{gameId}/{version}/` 路径下。Play 先拉 `manifest.json` 再加载入口，天然证明「文件来自远端产物地址」。（与后端语言无关）

3. **对象存储边界严格用 S3 SDK 抽象。**
   所有存储读写走 `boto3`，业务代码里**不出现本地文件写入**——这是「不接受的交付」里明确卡的点。

4. **Multi-Agent 拆分（LangGraph 节点）：**
   `Planner`（创意 + 素材 → game spec）→ `Designer`（机制 / 美术 / 数值）→ `Coder`（产出 HTML5 bundle）→ `Sandbox QA`（gVisor 沙箱执行 + 安全扫描）→ `Packager`（上传 OSS + 写 meta），失败走回边重试。每步输入输出写入 `agent_logs` 表，供前端展示步骤流。

5. **认证与 OAuth：**
   `fastapi-users` 提供邮箱密码 + 第三方登录；OAuth 回调与账号绑定在后端完成，前端只持有 session token。第三方登录按需求可「给出设计 + 真实跑通其一」。

## 4. 部署：Docker Compose 服务清单（5 个）

| 服务 | 内容 | 对应需求 |
| --- | --- | --- |
| `web` | Next.js 前端 | 前端 |
| `api` | FastAPI 后端 + Celery 任务投递 | 后端 |
| `worker` | Celery worker（跑 LangGraph 生成链路） | 异步任务 / Agent |
| `postgres` | PostgreSQL | 数据库 |
| `redis` | Celery broker + 缓存 | 异步任务 |
| `minio` | S3 兼容对象存储 | 对象存储 |

> 两个应用语言 → 两个 Dockerfile，但仍是 `docker compose up` 一键启动。

---

## 5. 待定 / 可替换的小选择

| 位置 | 当前选择 | 备选 | 取舍 |
| --- | --- | --- | --- |
| 任务队列 | Celery | ARQ | Celery 成熟、面试官认；ARQ 更轻、async 原生、与 FastAPI 更搭 |
| 认证 | fastapi-users | Authlib 自拼 JWT | fastapi-users 最省事；Authlib 完全手控 |
| 前端 | Next.js | Vite + React SPA | Next.js 有 SSR、结构规范；Vite 更轻，省掉一个 Node web server |

---

## 6. 选型如何覆盖测试硬性要求

| 测试硬要求 | 对应选型 |
| --- | --- |
| 不接受纯 CRUD，必须有 Create Agent 生成链路 | LangGraph 多 Agent 编排 + Celery 异步任务 |
| Play 必须动态加载远端文件，禁止本地写死 | manifest 协议 + MinIO + 沙箱 iframe |
| 对象存储须可无缝迁移到真实 OSS，禁止本地文件替代 | boto3（S3 SDK）+ MinIO，仅换 endpoint |
| AI 生成须可扩展到真实模型 / Agent Harness | LangGraph + langchain-openai，接真实 GPT-5.5 |
| 推荐 Docker Compose 一键启动 | 6 服务 compose |
| 邮箱登录 + 第三方登录设计 | fastapi-users + httpx-oauth |
| 系统设计文档放 docs 目录 | 本文件位于 `docs/` |
